# exp_000 — CPU spectral retrieval + pool fallback
- Owner: Pratham · Date: 2026-09-24 · Code: `casmi_spectral_retrieval_cpu.py` · Config: `configs/exp_000.yaml`

## Method
1. Per test spectrum: train spectra within max(0.01 Da, 20 ppm) of the raw precursor m/z; keep the 256 nearest by mass.
2. Greedy cosine, 0.01 Da tolerance, raw normalized intensities. Best score per ik14 across the molecule's spectra.
3. Ranking: spectral hits with score ≥ 0.20 (max 12) → pool candidates by (in_train, in_coconut, adduct-shift rank, mass error) → remaining spectral hits. Max 25.

## Results
| metric | value |
|---|---|
| public LB | **0.127** |
| local C1/C2/C3 | not measured (no harness yet) → exp_001 |

## Audit (to verify in exp_001, fix in 002–003)
1. 256-candidate cap by mass distance drops the true compound (biggest suspect).
2. Train matched on raw precursor m/z → same-adduct only.
3. Missing adducts: [M-H2O+H]+, [M-2H2O+H]+, [M-H2O-H]-, [M+CH2O2-H]- → wrong neutral mass for pool lookup.
4. Pool isomers ranked by mass error → effectively random within a formula.
5. No cleaning (precursor peak kept, no floor, no intensity transform).
6. 20 ppm pool tolerance, not measured for timsTOF.
7. Dedup by SMILES rather than metric ik14.
8. Cl⁻ offset off by one electron mass.

## Verdict
Baseline. Superseded once exp_002 lands. Kept runnable for regression checks.

# exp_001 — Validation harness + exp_000 loss decomposition

- Owner: Pratham · Date: 2026-09-24 · Branch: `exp/001-val-harness` · Parent: exp_000 · Config: `configs/exp_001.yaml`

## Hypothesis

exp_000 loses most of its MRR to candidate generation (truth never scored), not to ranking.
Falsified if `cand_not_top25` + `hit@2-25` > `reachable_missed` in C1.

**Result:** Partially confirmed. In C1, candidate generation is strong (recall 0.996). But in C2, ranking is the dominant problem: 137 molecules have truth in candidates but ranked below 25.

## Change vs parent

No model change. Adds: frozen val set, C1/C2/C3 regimes, Predictor interface, exp_000 port (verified identical to the original on 5 molecules), Kaggle runner sharing the same code.

Measurement. All classes.

2. Artifacts: Loss buckets and 20 worst molecules per regime successfully generated. [PASS]
3. Data Leakage: leak_hits = 0 confirmed in C2/C3 via tautomer-twin exclusion. [PASS]

## Failure analysis

- **C2 cand_not_top25 = 137** — pool isomers ranked by mass error = effectively random. Audit #4 confirmed. This is the #1 problem.
- **C2 reachable_missed = 30** — missing adducts ([M-H2O+H]+, [M-2H2O+H]+, [M-H2O-H]-, [M+CH2O2-H]-) and loose tolerance. Audit #3 confirmed.

- **16/250 metric ik14 ≠ raw ik14** — tautomer mismatch confirmed. Twin exclusion fixes it.

## Verdict: keep

Harness is the measurement tool for all future experiments.

exp_002: fix adducts + 10 ppm tolerance + metric-ik14 dedup → recover 30 reachable_missed.
Then exp_003: Tanimoto ranker for pool candidates → fix 137 cand_not_top25 (biggest single gain expected).

# ADR-001 — Retrieval + learned ranking first; de novo generation last
- Status: proposed (confirm with teammate)
- Date: 2026-09-24

## Context
- The metric only rewards an exact 2D match (InChIKey14) within 25 guesses.
- Class 1 (public spectra exist) and class 2 (in PubChem/COCONUT) are reachable by retrieval over train + pool.
- On public benchmarks (MassSpecGym) exact-match top-1 for de novo generation is near zero.
- exp_000 at 0.127 vs leader 0.417 — the gap is plausibly explained by retrieval bugs and random class-2 ranking (plan §2).

## Options
| option | pros | cons |
|---|---|---|
| A. Transformer spectrum→SMILES | covers class 3 in principle | near-zero exact match; expensive; no help for class 1/2 |
| B. Retrieval + heuristic ranking | cheap, fixes biggest losses | ceiling on class 2 |
| C. B + learned spectrum encoder as a scorer + LTR reranker | reuses our transformer; attacks class 2 | needs clean leave-structure-out training data |

## Decision
C. The transformer is repurposed as a spectrum encoder (fingerprint head / contrastive), not a SMILES decoder.

## Consequences
We stop investing in the SMILES-decoding baseline. Class 3 is handled later by analog edits (exp_009).

## Revisit if
Fitted class-3 share from LB calibration > 0.3, or C1+C2 plateau with headroom only in C3.

# ADR-002 — Validation protocol
- Status: proposed
- Date: 2026-09-24

## Context
- The visible `test.parquet` is copied from train → any score on it is leaked (identical spectra). Never tune on it.
- Public LB = partial test, limited submissions → too noisy/slow to iterate on.
- The test is timsTOF natural products; `enveda-np-examples` (250 molecules, 1,151 spectra) is the only same-instrument, same-pipeline NP set.

## Decision
- Query set: enveda-np-examples, grouped by molecule (ik14). Split frozen in `data/val_ik14.txt`, committed.
- Three regimes per run:
  - **C1**: reference = train minus enveda-np-examples rows.
  - **C2**: reference = train minus all rows with the query ik14; pool keeps it.
  - **C3**: C2 + drop the query ik14 from the pool.
- Report MRR, Recall@cand, Recall@25 per regime + est. LB + runtime.
- Anything trained (encoder, reranker) must exclude val ik14 from its training data. Reranker training queries: leave-structure-out from NP-rich libs (riken, gnps, msdial, mona, massbank), QTOF preferred.
- Every run dumps its 20 worst molecules for failure analysis.

## Known bias
enveda-np compounds were chosen to be common → C1 here is optimistic vs the real test. Track deltas, trust the LB calibration for absolute level.

## Revisit if
Local est. LB and public LB move in opposite directions on two consecutive submissions.

# CLAUDE.md — Standing rules for the implementer

You are the **implementer** for the CASMI26 repo. Architecture decisions are made
outside this repo and arrive as `plan.md`. Your job: execute `plan.md` exactly,
measure honestly, report back in `handoff.md`.

## Workflow (every session)
1. Read `plan.md`, `docs/decisions.md`, the last 3 entries of `experiments/exp-log.md`.
2. Implement only what `plan.md` scopes. Anything outside scope → write it under
   "Open questions" in `handoff.md`; do not do it.
3. Stop at each acceptance gate. If a gate fails, do not "fix forward" into the next
   phase — record the failure and stop.
4. Append every run to `experiments/exp-log.md` (format below), overwrite `handoff.md`.
5. Commit with message `exp_NNN: <one line>`.

## Hard rules
- **Never** modify the frozen V27 artifacts (pool npz, FPNet checkpoints, GBDT rankers).
  Wrap them; don't edit them.
- **Never** make a keep/discard decision from n=60. n=60 is a smoke test only.
  Decisions use the full validation set with paired bootstrap CIs (see Eval protocol).
- **Never** tune on the test file. The test file's labels are unknown; the only
  allowed use is label-free calibration (e.g. ppm offset), and it must be logged.
- **Leak check is mandatory** on every run: `leak_hits` must be 0 or the run is invalid.
- Every experiment has a config file in `configs/exp_NNN.yaml`. No magic numbers in code.
- Deterministic: fixed seeds, sorted iteration, log the git hash in every result row.
- If a run takes >2× the time `plan.md` estimates, stop and report, don't let it run overnight blind.

## Eval protocol
- Report per regime (C1 / C2 / C3): MRR, Recall@cand, Recall@25, n.
- Report **paired bootstrap 95% CI of the delta vs the anchor** (1,000 resamples over
  molecules). The anchor is named in `plan.md`.
- A change "works" only if the CI lower bound of the target-regime delta is > 0 **and**
  the C1 delta CI lower bound is > −0.01 (C1 non-inferiority).
- Estimated LB uses the class weights in `docs/decisions.md`; always print them.
